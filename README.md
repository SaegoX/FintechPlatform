# 📑 Микросервисная B2B-финтех платформа (P2B кредитование)

**Краткое описание:**  
MVP платформы краудлендинга, где Заёмщики (бизнес) подают заявки на финансирование, а Инвесторы вкладывают средства и получают процентный доход.  
Архитектура строится по принципам событийно-ориентированного микросервисного подхода (EDA), DDD и Clean Architecture.

---

|---------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------|
| **Бизнес-цель**           | Создать минимально жизнеспособный продукт (MVP) платформы кредитования P2B.                                                                        |
| **Техническая цель**      | Изучить и применить на практике передовой стек технологий экосистемы .NET, соответствующий уровню Middle / Middle+ Developer.                      |

## 🗺️ 3. Архитектура микросервисов и их зоны ответственности

Система разделена на **3 независимых сервиса** и **1 инфраструктурный шлюз**:

### 🔀 YARP API Gateway (Шлюз)
- Принимает все запросы от внешнего мира.
- Перенаправляет их на нужные микросервисы.
- Выполняет первичную проверку JWT-токенов.

### 💰 Loan Service (Сервис займов)
- **База данных:** `Fintech_Loans_Db`
- **Функции:**
  - Создание заявок на займы.
  - Расчёт графиков платежей.
  - Управление жизненным циклом займа (`Created → Repaid`).

### 💳 Billing Service (Сервис транзакций и кошельков)
- **База данных:** `Fintech_Billing_Db`
- **Функции:**
  - Ведение виртуальных балансов пользователей.
  - Проведение транзакций (пополнение, списание, перевод между инвестором и заёмщиком).
- **Особые требования:** Повышенная консистентность данных.

### 👤 Identity Service (Инфраструктурный слой вокруг Keycloak)
- **База данных:** Внутренняя БД Keycloak.
- **Функции:**
  - Регистрация пользователей.
  - Аутентификация и авторизация.
  - Разделение ролей: `Investor`, `Borrower`, `Admin`.

## 📜 4. Пошаговый план эволюции (Памятка для разработки)

| Этап | Название                             | Ключевые действия                                                                                      |
|------|--------------------------------------|--------------------------------------------------------------------------------------------------------|
| 1    | **Монолитное ядро (Логика займов)**  | Разработка слоёв Domain и Application для Loan Service. Настройка CQRS.                                |
| 2    | **База данных и тесты**              | Подключение EF Core 10 и PostgreSQL. Unit-тесты логики и интеграционные тесты с Testcontainers.        |
| 3    | **Контейнеризация**                  | Создание Dockerfile и docker-compose для запуска сервиса и БД одной командой.                          |
| 4    | **Разделение на микросервисы**       | Создание Billing Service, настройка YARP API Gateway, связывание через RabbitMQ (MassTransit).         |
| 5    | **Кэширование и безопасность**       | Интеграция Redis для кэширования списка активных займов. Развёртывание Keycloak для защиты эндпоинтов. |
| 6    | **Трассировка и CI/CD**              | Внедрение OpenTelemetry + Jaeger для сквозной трассировки. Написание пайплайна GitHub Actions.         |
